# Application Shell, Signal Monitor & Status UI — EARS Specs

Traces to `docs/llds/app-ui.md`.

## Signal Monitor

- [x] **UI-MONITOR-001**: The system shall initialize each channel's (`midi`, `dragonframe`) last-activity value to a "never seen" sentinel, distinct from any real timestamp, at startup.
- [x] **UI-MONITOR-002**: The system shall compute liveness using a monotonic clock, such that a channel is reported live only while its last-activity value is not the "never seen" sentinel and the elapsed monotonic time since that value is strictly less than the liveness window (proposed 2.0s).
- [x] **UI-MONITOR-003**: While a channel's error flag is set (MIDI: Native Mode handshake failure per `MIDI-NATIVE-003`, only possible under a profile with `has_native_mode` true; Dragonframe: listener bind failure per `OSC-LISTEN-003`), the system shall report that channel's display state as error, taking precedence over both live and quiet.

## Controller Profile Selector

- [x] **UI-PROFILE-001**: The system shall display a Controller Profile dropdown populated from the discovered, merged Controller Profile list (`PROFILE-LOAD-001`/`003`/`004`, see `docs/specs/midi-input.md`), defaulting the active selection to the profile named "nanoKONTROL Studio" on launch (`MIDI-PROFILE-004`) regardless of that list's display order.
- [x] **UI-PROFILE-002**: When the user changes the Controller Profile dropdown, the system shall apply the change immediately, with no separate Apply step (`MIDI-PROFILE-005`/`006`, see `docs/specs/midi-input.md`).
- [x] **UI-PROFILE-003**: While the active Controller Profile's `setup_hint` is present and non-empty (`PROFILE-LOAD-009`, see `docs/specs/midi-input.md`), the system shall display it verbatim as a one-line hint beneath the dropdown; while it is absent or empty, no hint line shall be shown.
- [x] **UI-PROFILE-004**: While the config-file failure count (`PROFILE-LOAD-011`, see `docs/specs/midi-input.md`) is greater than zero, the system shall display a one-line, count-only indicator near the Controller Profile dropdown (e.g. "2 controller config files failed to load"), independent of and able to be shown simultaneously with the `UI-PROFILE-003` setup hint; while the count is zero, no such indicator shall be shown. This indicator shall not display individual file names or error messages in the main window.

## Status UI

- [x] **UI-STATUS-001**: The system shall display two indicator rows, "MIDI signal" and "Dragonframe signal," each rendering a 3-state dot (live / error / quiet) and a short label, both derived from a single Signal Monitor read per UI update tick.
- [x] **UI-STATUS-002**: While the MIDI channel has not yet connected to a device matching the active Controller Profile (per `MIDI-CONN-007`, see `docs/specs/midi-input.md`), the system shall display "Waiting for {active profile's name}…" as the MIDI row's secondary text; when connected, it shall display the connected device's name instead.
- [x] **UI-STATUS-003**: The system shall display the configured local listen port on the Dragonframe row, and the configured Dragonframe host and port in an editable "Sending to" field pair.
- [x] **UI-STATUS-004**: The system shall treat the indicator dot's live/error/quiet state and the row's secondary label (connection/device-name text) as independent signals; a channel may simultaneously display an error dot and a connected-device label (e.g., a physically connected controller whose Native Mode handshake failed), and this combination is intended, not a defect. Under the nanoKONTROL2 profile, the error dot never lights (`MIDI-NATIVE-005`), so this combination cannot occur for that profile.
- [x] **UI-CONFIG-001**: When the user edits the host, Dragonframe port, or listen port fields and presses Apply, the system shall validate and apply the new configuration; edits shall not take effect, and no rebind shall occur, before Apply is pressed. Applying a changed local listen port shall trigger the OSC Listener to close and rebind its socket (`OSC-LISTEN-006`, see `docs/specs/osc-io.md`).
- [D] **UI-CONFIG-002**: Where settings persistence is enabled, the system shall persist the Dragonframe host, Dragonframe port, local listen port, and the selected Controller Profile across app launches (deferred pending a decision on whether phase 1 includes any persisted state).
- [x] **UI-CONFIG-003**: The host field and both port fields (Dragonframe port, listen port) shall each render with a fixed maximum width sized to their longest realistic content (an IPv4 address/short hostname, and a 5-digit port number respectively), rather than expanding to fill the layout's available width.
- [x] **UI-CFGDLG-001**: The system shall display a "Configuration" button directly beneath the Controller Profile dropdown; activating it shall open the Configuration Dialog (below) as a modal window. The dialog instance shall be created once and reused on every activation, not rebuilt from scratch each time.

## Mapping View

**As of 2026-07-23, the Mapping View renders only the fader rows' Group-axis grid (one row per Bank — `bank_count` rows, 8 for both bundled Korg profiles) — every other row has moved to the Configuration Dialog** (`UI-CFGDLG-*` below). The table has 3 columns — Name, MIDI, Target — the same 3 that survived the same-day Trigger/Target-type column removal.

- [x] **UI-MAP-001**: The Mapping View shall render exactly one row per Bank's fader (`bank_count` rows total — 8 for both bundled Korg profiles — in Bank order, `bank_count` derived from the active profile per `MAP-CONFIG-002`/`006`, see `docs/specs/static-mapping.md`), showing that fader's name, MIDI source, and its Target cell (the Group axis-picker grid, `UI-MAP-014`). No other control — Knob, Mute, Solo, transport/marker buttons, Previous/Next Track, the Scene button, or the jog wheel — is rendered as a row in this view; each is rendered instead in the Configuration Dialog (`UI-CFGDLG-002`).
- [x] **UI-MAP-002**: Every row rendered in the Mapping View (`UI-MAP-001`) shall be editable — the Group axis-name/min/max values within the Target cell (`MAP-AXIS-004`, see `docs/specs/static-mapping.md`). The Mapping View shall offer no target-*type* choice for any row; the engine-wide OSC axis/OSC encoder mode is controlled from the Configuration Dialog's Fader row (`UI-CFGDLG-003`), not from this view.
- [x] **UI-MAP-018**: The Mapping View shall render exactly 3 columns — Name, MIDI, Target — omitting Trigger and Target type entirely. Every fader row shall display its 5 Group pickers (`UI-MAP-014`) regardless of the engine-wide fader mode's current value (`MAP-AXIS-010`, see `docs/specs/static-mapping.md`) — the row's displayed content does not change with that mode, though the engine's actual dispatch does. `MappingEngine.set_fader_mode` shall not be called from anywhere in this view; it is called only from the Configuration Dialog's Fader row (`UI-CFGDLG-003`). The system shall additionally render a header row of 5 column letters, "A" through "E" left-to-right, as an actual row of the same table (not a separate widget) so its column boundaries match every fader row's Group picker columns.
- [x] **UI-MAP-004**: For each of a fader row's 5 Group pickers, the system shall recompute its candidate list from `AxisDiscovery.axes` on every UI update tick (the same tick that updates the status indicators), not only when the picker is opened or Rescan is pressed, and shall not accept a free-text or arbitrary name (`MAP-AXIS-003`, see `docs/specs/static-mapping.md`); all 5 pickers on a row share the same candidate list, since axis discovery is project-wide, not per-Group.
- [x] **UI-MAP-005**: While `AxisDiscovery.axes` is `None` (never queried, or a query outstanding), the system shall render every Group picker's candidate list as disabled with the text "Discovering…"; while `AxisDiscovery.axes` is an empty dict (queried, zero axes found), the system shall render every Group picker as disabled with the text "No axes found"; otherwise the system shall render every Group picker enabled with the discovered names, sorted for stable display order.
- [x] **UI-MAP-006**: When the user selects an axis name or edits a min/max field on one Group's picker within a fader row set to OSC axis, the system shall call `MappingEngine.set_axis_target(key, group, name, min, max)` — `group` identifying which of the row's 5 pickers was edited — once both a name is selected and both fields parse as real numbers, with no separate save step and with no requirement that `group` equal the currently active Group (`MAP-GROUP-008`); until then, that Group's assignment continues driving whatever target it was last actually given (`MAP-AXIS-006`).
- [x] **UI-MAP-007**: The system shall accept any value parseable as a real number in any Group picker's min/max fields, including `min > max` or `min == max` (`MAP-AXIS-002`), and shall not reject or warn on either case; text that fails to parse as a number shall not be applied, and that picker's last successfully-applied target (if any) shall remain in effect, with no error dialog.
- [x] **UI-MAP-008**: If a fader row's Group picker's configured axis name is no longer present in `AxisDiscovery.axes`, the system shall continue showing that name as that picker's current selection (greyed to indicate it cannot be re-selected once deselected), rather than clearing or replacing it, and shall not alter that Group's configured target as a result (`MAP-AXIS-006`, see `docs/specs/static-mapping.md`). This is evaluated independently per Group picker — one Group's assignment going stale does not affect any other Group's picker on the same row.
- [x] **UI-MAP-009**: When the user activates "Rescan axes," the system shall call `OscListener.rescan()` and shall not modify any row's already-configured target, in any Group, as a result of the call itself.
- [x] **UI-MAP-010**: The (Bank, Group) axis-name/min/max table persists across application launches via the Preset Store (`MAP-STORE-001`ff., see `docs/specs/static-mapping.md`); no other piece of Mapping View state is persisted (the engine-wide fader mode and every Configuration Dialog row's content reset to their defaults on next launch — see `UI-CFGDLG-*` below).
- [x] **UI-MAP-011**: On initial render, the system shall show each fader row with all 5 Group pickers visible; a Group picker whose (Bank, Group) pairing has a value loaded from the Preset Store (`MAP-STORE-002`) shall show that value pre-selected, and a Group picker with no persisted value shall show no name selected (`MAP-AXIS-008`, see `docs/specs/static-mapping.md`).
- [x] **UI-MAP-014**: Each of the `bank_count` fader rows shall show 5 axis-name pickers, one per Group, ordered left-to-right as Group 1 through Group 5, replacing the single picker of the pre-Phase-6 design; each picker independently applies `UI-MAP-004` through `UI-MAP-008`.
- [x] **UI-MAP-015**: The system shall render a Group indicator row, positioned above the fader rows within the Target column's space, showing 5 lights ordered left-to-right as Group 1 through Group 5; the light corresponding to the currently active Group (`MAP-GROUP-002`, see `docs/specs/static-mapping.md`) shall render blue, and every other light grey; this row shall be recomputed every UI tick, the same cadence as `UI-MAP-004`'s picker candidates and `UI-CFGDLG-007`'s Solo row text. This indicator is unique to the Mapping View; the Configuration Dialog does not render one (`UI-CFGDLG-002`).
- [x] **UI-MAP-017**: When the user clears one Group picker's selection back to "no axis chosen," the system shall call `MappingEngine.clear_group_axis_target(key, group)` (`MAP-GROUP-009`, see `docs/specs/static-mapping.md`) — leaving the fader in OSC axis (direct) mode and every other Group's assignment for that fader unaffected. This is distinct from, and shall not itself change, the engine-wide fader mode (`UI-CFGDLG-003`, `MAP-AXIS-010`).

## Configuration Dialog

A modal `QDialog`, opened per `UI-CFGDLG-001` above. Holds every control's assignment that isn't the Mapping View's fader-to-axis grid (`UI-MAP-001`ff.), plus the engine-wide fader mode switch.

- [x] **UI-CFGDLG-002**: The Configuration Dialog shall render exactly one row per control *type* for Knob (pot), Mute, and Solo — not one row per physical instance (`bank_count` rows each) — describing each type's shared behavior once; every other control with only one physical instance (Play, Record, Rewind, Fast Forward, Stop, Cycle, Previous/Next Marker, Previous/Next Track, and, where the active profile declares them, the Scene button and the jog wheel's two rows) shall each render exactly one row, matching its pre-2026-07-23 Mapping View content and per-profile presence rules (`MAP-PROFILE-003`, `MAP-CONFIG-004`, `MAP-GROUP-006`, see `docs/specs/static-mapping.md`) unchanged. No row in this dialog shall offer MIDI CC-number editing.
- [x] **UI-CFGDLG-003**: The Configuration Dialog shall render a "Fader" row (row 0 of the table, same as every other row) whose Target cell holds a single two-state control (Axis mode / Encoder mode) reflecting `MappingEngine.is_axis_mode()`, recomputed every UI tick; activating it shall call `MappingEngine.set_fader_mode(axis: bool)`, applying to all `bank_count` faders simultaneously (`MAP-AXIS-010`, `docs/specs/static-mapping.md`). This is the only interactive cell in the dialog; the Fader row's Name/MIDI cells are ordinary read-only text.
- [x] **UI-CFGDLG-006**: The Configuration Dialog's Knob (pot) and Mute rows shall each display static descriptive text of their bank-derived behavior (`MAP-BANK-001` through `004`, see `docs/specs/static-mapping.md`) rather than a live per-Bank value, and shall not be recomputed per UI tick — unlike the Solo row (`UI-CFGDLG-007`), neither depends on the active Group.
- [x] **UI-CFGDLG-007**: The Configuration Dialog shall render exactly one row named "Solo 1-{N}" (`N` = the active profile's Solo count — "Solo 1-8" for both bundled profiles) for the Solo controls, not rendered as separate per-button rows; the row shall show the Solo CCs' MIDI source range and shall not be editable. Its Target text shall be recomputed every UI tick from the active Group `g` (`MAP-GROUP-002`) and the active profile's `bank_count` as "select-AX{1+bank_count·(g-1)} – select-AX{bank_count+bank_count·(g-1)} (Group {g})" (`MAP-WS-002`, see `docs/specs/static-mapping.md`) — e.g. "select-AX9 – select-AX16 (Group 2)" for a `bank_count = 8` profile.
- [x] **UI-CFGDLG-008**: While the active Controller Profile's `has_jog_wheel` is true (the nanoKONTROL Studio), the Configuration Dialog shall render two further rows for the jog wheel, since it is not itself an opinionated-map entry (`docs/specs/static-mapping.md § Jog Wheel Frame Stepping`): a row named "Jog Wheel" with Target "stepForward / stepBackward", and a row named "Jog Wheel (Arc)" with Target "Option+Shift+Right / Option+Shift+Left"; both rows shall show MIDI source "CC110, ch{profile's default channel}", and neither shall be editable. While `has_jog_wheel` is false (the nanoKONTROL2), the dialog shall render neither row.
- [x] **UI-CFGDLG-009**: The Configuration Dialog shall render two additional fixed rows, "Previous Track" and "Next Track," Target text "Previous (wraps 5→1)" / "Next (wraps 5→1)" respectively (`MAP-GROUP-004`, see `docs/specs/static-mapping.md`). Neither row shall be editable. Where a profile declares only one of `previous_track`/`next_track` (`MAP-GROUP-006`), the dialog shall render only the corresponding row.
- [x] **UI-CFGDLG-010**: When the active Controller Profile switches (`MIDI-PROFILE-005`, see `docs/specs/midi-input.md`), the system shall rebuild the Configuration Dialog's full row set from the newly-active profile, such that a row whose presence is profile-conditional (Scene button, jog wheel, Previous/Next Track) is added or removed to match the new profile rather than continuing to display the outgoing profile's row set.

## Main Window Shell (Phase 8)

- [x] **UI-SHELL-001**: The system shall present a header, a body, and a footer as the main window's three stacked regions; the header and footer shall render identically and remain interactive regardless of which body page is currently showing.
- [x] **UI-SHELL-002**: The header shall contain, left to right: the application name; the MIDI and Dragonframe 3-state indicators, each rendering both its dot and its existing short status text (`UI-STATUS-001`/`002`, unchanged); a ⚙ button opening the Settings Dialog (`UI-SETTINGS-001`); the Controller Profile dropdown (`UI-PROFILE-001`, unchanged); and the Group selector (`UI-GROUPSEL-001`).
- [x] **UI-SHELL-003**: The body shall be a two-page stack: page 0 is the Controller View (`UI-CTRLVIEW-*`); page 1 is Table View, containing the existing Mapping View (`UI-MAP-*`, unchanged) and a button opening the existing modal Configuration Dialog (`UI-CFGDLG-*`, unchanged).
- [x] **UI-SHELL-004**: The footer shall contain the existing Dragonframe connection summary text and exactly one toggle button; the button shall read "Table View" while the Controller View page is showing and "Controller View" while the Table View page is showing, and activating it shall switch the body to the other page without altering header state, without rebuilding either page's content, and without resetting the Controller Profile dropdown or Group selector.
- [x] **UI-SHELL-005**: The Controller View page shall be the body's default page on application launch.

## Group Selector (Phase 8)

- [x] **UI-GROUPSEL-001**: The system shall render a horizontal row of 5 buttons labeled "A" through "E" left to right (the same `_GROUP_LETTERS` sequence `UI-MAP-015`'s indicator already uses), in the shared header. The button corresponding to the currently active Group (`MAP-GROUP-002`) shall render with an explicitly-set background/text color matching `_GroupIndicatorRow`'s own active-light color (`ACTIVE_GROUP_COLOR`); every other button shall render with the matching inactive color (`INACTIVE_GROUP_COLOR`). This coloring shall be set explicitly on every UI tick, not left to a `QPushButton`'s native `:checked` pseudo-state, which this app's global stylesheet does not define and which was found (by running the app and looking at it) to render inconsistently depending on window-focus state.
- [x] **UI-GROUPSEL-002**: When the user activates a Group selector button for a Group other than the currently active one, the system shall call `MappingEngine.step_active_group(direction)` (`MAP-GROUP-013`) one or more times — the fewest calls needed to reach the target Group, taking the wraparound direction when it is shorter — such that the engine ends on exactly the target Group with the same per-step dedup/position-discard behavior (`MAP-GROUP-011`) as an equivalent sequence of Track ◄/► presses. Activating the already-active Group's button shall call it zero times.

## Settings Dialog (Phase 8)

- [x] **UI-SETTINGS-001**: Activating the header's ⚙ button shall open a modal Settings Dialog, created once and reused on every activation, containing exactly the fields `UI-STATUS-003`, `UI-CONFIG-001`, `UI-CONFIG-002`, `UI-CONFIG-003`, `UI-PROFILE-003`, and `UI-PROFILE-004` already describe (host/port fields and Apply, the per-profile setup hint, the config-load-failure count) — unchanged validation, persistence, and Apply behavior; this dialog is a new container for existing fields, not a new field or a new mechanism.
- [x] **UI-SETTINGS-002**: The Settings Dialog shall not render any per-control mapping summary row (Knob, Mute, Solo, Fader mode, or any `UI-CFGDLG-*` row); that content remains exclusively in the Configuration Dialog (`UI-CFGDLG-*`), reachable only via Table View.

## Control Descriptor (Phase 8, revised Phase 1.2)

- [x] **UI-CTRLDESC-001**: `build_control_descriptors(fader_rows, configuration_rows, active_controller)` shall return one `ControlDescriptor(key, label, control_type)` per `RowView` in `fader_rows` (`build_fader_rows()`'s output, `UI-MAP-001`); then one per key in `active_controller.knob_to_fader`, one per key in `active_controller.mute_to_fader`, and (where `active_controller.websocket_keys` is not `None`) one per key in `active_controller.websocket_keys.solos` (`UI-CTRLDESC-004`); then one per `RowView` in `configuration_rows` whose key was not already produced by any of the above; then one per `active_controller.control_names` entry whose key was not already produced by any of the above — each group preserving its own source's order — with `label` equal to that row's `.name` (fader/configuration groups), `control_names.get(key, "Knob"|"Mute")` (Knob/Mute groups), the literal string `"Solo"` (Solo group), or the `control_names` value (fallback group) as appropriate. A control present in more than one source produces exactly one descriptor, from whichever source listed it first.
- [x] **UI-CTRLDESC-002**: `control_type` reflects the control's physical shape, not its assigned function: every descriptor built from `fader_rows` is `"fader"`; every descriptor built from the Knob expansion (`active_controller.knob_to_fader`) is `"rotary"`; every descriptor built from the Mute/Solo expansion is `"button"`; a `configuration_rows`/`control_names`-fallback descriptor is `"jog"` where its key is the Korg jog wheel's two fixed rows or its key's tag is `"grid_vsn1_jog"`/`"grid_vsn1_jog_button"`, `"fader"` where its key is in `active_controller.fader_keys` (fallback only), and `"button"` otherwise. No other `control_type` value is produced.
- [x] **UI-CTRLDESC-003**: Where `fader_rows` is empty (e.g. VSN1, which has no faders), `build_control_descriptors` shall return no `"fader"`-type descriptor and shall not raise or otherwise special-case the empty list. Where `active_controller.control_names` contains a key with no corresponding `opinionated_map` entry (e.g. VSN1's buttons and jog wheel, which are not wired to any default action), that control shall still produce a descriptor via the `control_names` fallback, not be silently omitted.
- [x] **UI-CTRLDESC-004**: Knob, Mute, and Solo shall each be expanded into one descriptor per real key (`active_controller.knob_to_fader`/`mute_to_fader`/`websocket_keys.solos`), not the single collapsed `KNOB_ROW_KEY`/`MUTE_ROW_KEY`/`SOLO_ROW_KEY` summary row `configuration_rows` carries for Table View — per-bank Control Grouping (`UI-CTRLGROUP-001`) needs to know which bank each belongs to, which the collapsed row cannot express. The collapsed summary rows themselves shall not also produce a descriptor (no duplication). `active_controller.knob_to_fader`/`mute_to_fader` cover PBF4's Rotary/Button elements identically to a Korg profile's Knob/Mute (`GRID-CTRL-011`), so this expansion needs no controller-family branch.

## Inspector Editor Registry (Phase 8, revised Phase 1.2)

- [x] **UI-INSPREG-001**: `has_editor(control_type, bank_derived=False)` shall return `True` for `control_type` in `{"fader", "rotary"}` regardless of `bank_derived`, and `False` for `"jog"` or any unrecognized `control_type`, regardless of `bank_derived`.

## Controller View (Phase 8)

- [x] **UI-CTRLVIEW-001**: The Controller View page shall render an expandable hierarchy (`UI-CTRLTREE-001`ff., Phase 1.1) with one leaf row per `ControlDescriptor` from `build_control_descriptors(build_fader_rows(engine), build_configuration_rows(engine), engine.profile)` (`UI-CTRLDESC-001`), each nested under the `ControlGroup` (`UI-CTRLGROUP-001`ff.) it belongs to, in that group's `controls` order.
- [x] **UI-CTRLVIEW-002**: Each leaf row shall display its descriptor's `label`, and an assignment-summary text computed as follows: for a `"fader"` descriptor, `group_axis_picker_states(engine, key, axes)[active_group - 1]`'s current axis name formatted as "{name} · Axis" when present, or "Unassigned" when absent; for a `"rotary"` descriptor, `"Adjust {axis_name}"` where `MappingEngine.axis_target(fader_key, active_group)` is set and `rotary_action(fader_key)` is not `ROTARY_ACTION_NONE`, `"Adjust · no axis assigned"` where an axis target is unset, or `"Unassigned"` where the action is `ROTARY_ACTION_NONE`; for a descriptor whose key is in `active_controller.mute_to_fader`, the same pattern using `button_action(fader_key)` — `"Mute {axis_name}"`/`"Mute · no axis assigned"` for `BUTTON_ACTION_MUTE`, `"select-AX{N}"` (same formula as Solo, below) for `BUTTON_ACTION_SOLO`, `"Unassigned"` for `BUTTON_ACTION_NONE`; for a descriptor whose key is in `active_controller.websocket_keys.solos` (where not `None`), `"select-AX{N}"` computed from that key's position in `solos` and the active Group, matching `MAP-WS-002`'s own formula — never "Unassigned", since Solo's target is never actually unconfigured; for every other descriptor with a matching `RowView` in `build_configuration_rows(engine)`, that row's `target` text; for a descriptor with no matching `RowView` anywhere (a `control_names`-only control with no `opinionated_map` entry, e.g. an unwired VSN1 button), "Unassigned". This summary shall be recomputed every UI tick.
- [x] **UI-CTRLVIEW-003**: Selecting a leaf (physical-control) row shall visually highlight that row (and no other) and populate the Inspector (`UI-CTRLVIEW-005`ff.) for that row's descriptor; no row shall be selected by default; selecting (clicking) a group header row shall not change the selection or the Inspector (`UI-CTRLTREE-002`).
- [x] **UI-CTRLVIEW-004**: When the active Controller Profile switches, the system shall rebuild the control hierarchy from the newly-active controller (`UI-CTRLDESC-001`, `UI-CTRLGROUP-001`) and clear the current selection to "no selection" (`UI-CTRLVIEW-003`), rather than retaining a selection that may reference a key the new controller does not have.
- [x] **UI-CTRLVIEW-005**: While no control-list row is selected, the Inspector shall display a neutral placeholder and no editable fields.
- [x] **UI-CTRLVIEW-006**: While a `"fader"`-type row is selected, the Inspector shall display exactly one axis-name picker and one min/max field pair (`_SingleAxisTargetField`), bound to the selected descriptor's `key` and the currently active Group, reflecting and editing `MappingEngine.axis_target(key, active_group)` via `set_axis_target`/`clear_group_axis_target` exactly as `UI-MAP-004` through `UI-MAP-008` already specify for one Group — not the 5-Group grid `UI-MAP-014` renders.
- [x] **UI-CTRLVIEW-007**: While a control-list row is selected and `has_editor(descriptor.control_type, bank_derived)` is `False` (`UI-INSPREG-001`/`002`), the Inspector shall display a short read-only message indicating no settings are available for that control, alongside the same summary text `UI-CTRLVIEW-002` shows in the control list for that row.
- [x] **UI-CTRLVIEW-008**: When the active Group changes (`UI-GROUPSEL-002` or a Track ◄/► press) while a `"fader"`-type row is selected, the Inspector's single axis-target field (`UI-CTRLVIEW-006`) shall rebind to the newly-active Group's assignment for the same selected fader, without changing the control-list selection.
- [x] **UI-CTRLVIEW-009**: The Controller View shall apply no special handling for a Grid controller transitioning to a stale topology state mid-session; the control list and Inspector shall continue reflecting whichever topology was active when last built, matching Table View's existing unhandled-until-reselected behavior for the same condition.
- [x] **UI-CTRLVIEW-010** (Phase 1.2): While a `"rotary"`-type row is selected, the Inspector shall display one combo box (`_ActionComboField`) offering `ROTARY_ACTIONS`, bound to that control's fader key, reflecting and editing `MappingEngine.rotary_action`/`set_rotary_action`. While a `"button"`-type row whose key is in `active_controller.mute_to_fader` is selected, the Inspector shall display the same field offering `BUTTON_ACTIONS` instead, bound to `MappingEngine.button_action`/`set_button_action`. Either field's edit shall invoke the same persistence callback an axis-target edit invokes (`on_group_axis_changed`).

## Control Grouping (Phase 1.1)

- [x] **UI-CTRLGROUP-001**: `build_control_groups(descriptors, active_controller)` shall produce one `ControlGroup` of `kind == "channel"` per Bank 1..`active_controller.bank_count` that has at least one member, in Bank order, labeled `"Channel {N}"`. A descriptor belongs to Bank N if it is `bank_fader_keys[N-1]`; or `active_controller.bank_fader_key(key) == bank_fader_keys[N-1]`; or (where `websocket_keys` is not `None`) it is `websocket_keys.solos[N-1]`; or its key's `kind` is `"grid_pbf4_pot"`/`"grid_pbf4_button"` and its key's numeric index equals N.
- [x] **UI-CTRLGROUP-002**: Every descriptor not assigned to a channel group, and whose key's `kind` is not `"grid_vsn1_button"`/`"grid_vsn1_jog"`/`"grid_vsn1_jog_button"`, shall be placed in one group labeled `"Transport & Global"`, present only if at least one such descriptor exists.
- [x] **UI-CTRLGROUP-003**: A descriptor whose key's `kind` is `"grid_vsn1_button"` shall be placed in one group of `kind == "vsn1_buttons"` labeled `"Buttons"`; a descriptor whose key's `kind` is `"grid_vsn1_jog"` or `"grid_vsn1_jog_button"` shall be placed in one group of `kind == "vsn1_jog"` labeled `"Jog Wheel"`. Neither group shall be labeled or treated as a channel.
- [x] **UI-CTRLGROUP-004**: Where no descriptor resolves to a channel group and no VSN1-specific group applies, every remaining descriptor shall be placed in one group of `kind == "fallback"` labeled `"Controls"`, rather than being omitted.
- [x] **UI-CTRLGROUP-005**: Every descriptor passed to `build_control_groups` shall appear in exactly one returned group's `controls`; none shall be dropped and none shall appear in more than one group.

## Control Tree (Phase 1.1)

- [x] **UI-CTRLTREE-001**: The Controller View's control hierarchy shall render as a two-level tree: one top-level, collapsible item per `ControlGroup` (`UI-CTRLGROUP-001`ff., in that function's returned order), each containing one child (leaf) item per `ControlGroup.controls` entry, in that group's order.
- [x] **UI-CTRLTREE-002**: A group header item shall not carry the selectable flag; activating (clicking) it shall toggle its expanded/collapsed state and shall not change the current selection, the Inspector, or any MIDI/Dragonframe/mapping state.
- [x] **UI-CTRLTREE-003**: Activating (clicking) a group header while a leaf is selected shall leave that leaf's selection, highlight, and Inspector content unchanged; the tree's `currentItem()` shall never be left referencing a non-leaf (group header or empty-state) item after any focus-in event (regardless of platform) — if Qt's own focus handling would otherwise leave it so, the current item shall be cleared back to none.
- [x] **UI-CTRLTREE-004**: Multiple group headers may be expanded simultaneously; expanding or collapsing one group shall not change any other group's expanded/collapsed state.
- [x] **UI-CTRLTREE-005**: Rebuilding the hierarchy (`UI-CTRLVIEW-004`, a Controller Profile switch) shall reset every group's expanded state to collapsed and clear any active search text; a `refresh()` call (every UI tick) shall never rebuild the tree structure or alter any group's expanded state — only leaf item text may change.
- [x] **UI-CTRLTREE-006**: Where `build_control_groups` returns no `"channel"`-kind group for the active controller (e.g. VSN1-only), the hierarchy shall contain no group labeled `"Channel {N}"` for any N.

## Control Search (Phase 1.1)

- [x] **UI-CTRLSEARCH-001**: A search field shall be rendered directly above the control hierarchy. While its text is non-empty, a group shall be visible if its own label contains the search text (case-insensitive) or at least one of its leaf children's currently-rendered text (label plus assignment summary, `UI-CTRLVIEW-002`) contains it; a leaf shall be visible if its group matches on label, or the leaf's own rendered text matches.
- [x] **UI-CTRLSEARCH-002**: Every group that is visible under an active search (`UI-CTRLSEARCH-001`) shall be shown expanded, regardless of its expanded state before the search began.
- [x] **UI-CTRLSEARCH-003**: Changing the search text shall never change `_selected_key` or the Inspector's displayed content, whether or not the currently selected leaf remains visible under the active filter.
- [x] **UI-CTRLSEARCH-004**: The expanded/collapsed state of every group immediately before the search text first became non-empty shall be recorded; clearing the search text back to empty shall restore every group to that recorded state, not leave groups in whatever expanded state the search left them in.
- [x] **UI-CTRLSEARCH-005**: While the search text is non-empty and no group is visible under it, the hierarchy shall display a single, non-selectable row reading `"No matching controls."` and no group/leaf rows; that row shall not be present while the search text is empty or at least one group is visible.

## Threading and Shutdown

- [x] **UI-THREAD-001**: The system shall bridge MIDI events and OSC Listener datagrams from their background threads into the Qt main thread using thread-safe queues drained by a timer, fully draining each queue on every tick with no per-tick cap.
- [x] **UI-SHUTDOWN-001**: When the application quits, the system shall run each cleanup step (Native Mode release, MIDI port close, OSC Listener stop, UDP client socket close) with its own isolated error handling, such that a failure in one step does not prevent the others from running, and shall bound the overall shutdown sequence with a timeout before force-exiting.
