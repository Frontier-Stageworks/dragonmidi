# Intech Grid Support — EARS Specs

Traces to `docs/llds/intech-grid.md`. All requirements below are implemented and covered by `tests/test_grid_*.py` (`[x]`, per `CLAUDE.md`'s marker convention). A first real-hardware validation pass (2026-11-04, 2×PBF4 + 1×VSN1) exercised every requirement through Phase 1.2 except `GRID-TOPO-006`'s page-change case and a real module disconnect/reconnect while active — both still simulated-topology-only; see `docs/llds/intech-grid.md § Open Questions`'s item 21/Deferred-6 and the completion report for the full account, including two real-hardware bugs found and fixed (`GRID-DISCOVER-001`'s match substring, and the frame wire format `GRID-TOPO-001`/`002` describe). The Phase 1.3 VSN1-multiplicity generalization (`GRID-CTRL-003`/`004`/`012`/`013`, `GRID-MAP-003`, `GRID-APP-002`/`003`/`005`) and Named Controller resolution are unit- and integration-tested (`tests/test_grid_controller.py`, `tests/test_app_named_controller_wiring.py`) but not yet exercised against real multi-VSN1 hardware.

## Discovery

- [x] **GRID-DISCOVER-001**: The system shall detect Grid's USB-MIDI interface by fuzzy-matching the enumerated MIDI port name against a `match_substring` of `"grid"` (corrected 2026-11-04 against real hardware: a real Grid's MIDI port name is simply `"Grid"`, the bare USB product string, not the `"Intech Grid MIDI"` per-interface descriptor string earlier source research had assumed; `"grid"` still also matches that assumed fuller name), using the existing `MidiInputAdapter` discovery/auto-connect mechanism (`docs/specs/midi-input.md`) unchanged.
- [x] **GRID-DISCOVER-002**: The system shall detect Grid's USB-CDC interface by filtering enumerated serial ports against Grid's known VID/PID pairs (`(0x03eb, 0xecac)`, `(0x303a, 0x8123)`, `(0x2e8a, 0x1145)`); a port's name matching a `match_substring` of `"grid"` (corrected 2026-11-04 for the same reason as `GRID-DISCOVER-001`) may corroborate a match but shall never substitute for the VID/PID filter.
- [x] **GRID-DISCOVER-003**: If exactly one candidate Grid CDC port is found, the system shall open it at 2,000,000 baud and proceed to topology acquisition (`GRID-TOPO-*`).
- [x] **GRID-DISCOVER-004**: If more than one candidate Grid CDC port is found, the system shall not open any of them and shall report an ambiguous-chains status (`docs/llds/intech-grid.md § UI Implications`); Grid shall not become the active controller while more than one candidate remains.
- [x] **GRID-DISCOVER-005**: While no candidate Grid CDC port, or no matching Grid MIDI port, is found, the system shall remain in the same "waiting for device" state `docs/specs/midi-input.md` already defines for any controller with no connected device, rather than partially activating.
- [x] **GRID-DISCOVER-006**: The system shall discover and open both the Grid MIDI and Grid CDC interfaces without requiring Grid Editor, or any other companion application, to be running.

## Topology Acquisition

- [x] **GRID-TOPO-001**: The system shall parse Grid CDC byte traffic as `SOH` (`0x01`) / `EOB` (`0x17`)-delimited frames; a byte sequence that does not form a complete, well-formed frame before the next `SOH` shall be discarded without raising, and parsing shall resynchronize on the next `SOH`.
- [x] **GRID-TOPO-002**: From a frame whose heartbeat `TYPE` is `0` ("grid") or `1` ("gridmaster"), the system shall extract `hwcfg`, `x`, `y`, `rotation`, and `port_rotation`; from a `TYPE=1` frame specifically, the system shall additionally extract the current page number carried in that same transmission's `PAGEACTIVE` sub-frame.
- [x] **GRID-TOPO-003**: The system shall treat a frame whose heartbeat `TYPE` is anything other than `0` or `1` — `255` ("editor") specifically, and any other value the protocol does not define as a module — as not a Grid module; such a frame shall be recognized and discarded, not treated as a parse failure or a third kind of module.
- [x] **GRID-TOPO-004**: The system shall resolve a heartbeat's `hwcfg` to a supported module type (PBF4 or VSN1, `docs/llds/intech-grid.md § Module Definitions`) via a fixed lookup table; an `hwcfg` matching neither shall not raise and shall not, by itself, fail topology construction.
- [x] **GRID-TOPO-005**: The system shall treat two heartbeats reporting the same `(x, y)` with the same `hwcfg` and `rotation` as an ongoing liveness refresh of the same module, not as a new or changed module.
- [x] **GRID-TOPO-006**: The system shall classify each of the following as a structural topology change: a new `(x, y)` position appearing; an `(x, y)` position present in the current snapshot not reporting within Grid's own disconnect timeout (500ms); an `(x, y)` position reporting a different `hwcfg` or `rotation` than it previously reported; the gridmaster's reported current page changing. No other condition shall count as a structural change.
- [x] **GRID-TOPO-007**: The system shall not consider a topology settled until no structural change (`GRID-TOPO-006`) has occurred for a configurable settle duration (Phase 1 default: 500ms) and at least one `TYPE=1` ("gridmaster") heartbeat has been observed.
- [x] **GRID-TOPO-008**: An ordinary, unchanged heartbeat refresh of an already-known module shall not restart the settle duration in `GRID-TOPO-007`.
- [x] **GRID-TOPO-009**: The system shall derive each recognized module's normalized left-to-right rank by sorting every recognized module in a settled topology by absolute `x` ascending; this rank, not absolute `x`, shall be the basis for every logical-control numbering rule (`GRID-CTRL-002`, `GRID-CTRL-003`).
- [x] **GRID-TOPO-010**: If a settled topology contains any module — recognized or unrecognized — whose `y` differs from the rest, the system shall reject the topology as unsupported for Phase 1 and shall not construct a Grid runtime controller from it.
- [x] **GRID-TOPO-011**: An unrecognized module within a topology that otherwise satisfies `GRID-TOPO-010` shall be excluded from element enumeration and shall not, by itself, cause topology rejection.
- [x] **GRID-TOPO-012**: WHEN a structural topology change (`GRID-TOPO-006`) is detected while a Grid runtime controller built from a prior settled topology is active, THE SYSTEM SHALL mark that controller stale immediately, without attempting a live rebuild.

## Runtime Controller

- [x] **GRID-CTRL-001**: The system shall expose a Grid runtime controller's `bank_count` as the count of normalized PBF4 fader elements only, distinct from its total logical-control count (`docs/llds/intech-grid.md § Active Grid Controller`).
- [x] **GRID-CTRL-002**: The system shall number PBF4 faders, potentiometers, and buttons each `1..N` left-to-right across every PBF4 module in the normalized topology, independently of one another, such that a non-PBF4 or unrecognized module interposed between two PBF4 modules neither resets nor interrupts any of the three sequences.
- [x] **GRID-CTRL-003** (revised Phase 1.3): The system shall number VSN1's buttons globally left-to-right across every recognized VSN1 module in the normalized topology — module 1's buttons `1..12`, module 2's `13..24`, and so on — and shall tag each VSN1 module's jog and jog-button with that module's 1-based VSN1-instance ordinal (left-to-right among VSN1 modules only). **Accepted limitation, not an invariance claim**: with exactly one recognized VSN1 present, its identity is independent of its position in the row (ordinal is always `1`, matching the original Phase 1/1.2 guarantee); with two or more, reordering their relative left-to-right positions changes which ordinal — and therefore which logical identity — attaches to each, the same positional-not-persistent limitation `docs/llds/intech-grid.md § Persistence` already accepts for Bank numbering generally.
- [x] **GRID-CTRL-004** (revised Phase 1.3 — supersedes the Phase 1/1.2 requirement of the same ID, which restricted a topology to at most one recognized VSN1): The system shall support any number of recognized VSN1 modules in a single-row topology. A second or later recognized VSN1 module shall not, by itself, cause `UnsupportedTopology`; `GRID-CTRL-003`'s global numbering removes the logical-identity aliasing risk the prior restriction existed to prevent.
- [x] **GRID-CTRL-005**: IF two recognized elements of a settled, single-row topology would resolve to the same `(channel, message type, controller/note number)`, THEN THE SYSTEM SHALL NOT construct a Grid runtime controller from that topology, and shall report an address-collision outcome instead.
- [x] **GRID-CTRL-006**: The system shall not let one of two colliding elements (`GRID-CTRL-005`) silently override the other in a constructed address table; a detected collision shall abort construction entirely, not produce a partial table.
- [x] **GRID-CTRL-007**: A Grid runtime controller shall satisfy the same structural `ActiveController` shape (`name`, `default_channel`, `has_native_mode`, `has_jog_wheel`, `has_scene_button`, `bank_count`, `bank_fader_keys`, `fader_keys`, `knob_to_fader`, `mute_to_fader`, `fader_to_knob`, `opinionated_map`, `control_names`, `websocket_keys`, `group_keys`, `bank_fader_key()`, `matches()`) that `ControllerProfile` already satisfies, without itself being a `ControllerProfile` instance.
- [x] **GRID-CTRL-008**: The system shall report `has_jog_wheel = False` for a Grid runtime controller; VSN1's jog shall be represented as its own logical control (`("grid_vsn1_jog", None)`), not dispatched through the Korg-specific fixed-CC110 jog-wheel decode path.
- [x] **GRID-CTRL-009**: The system shall derive a Grid runtime controller's `default_channel` as the settled topology's current page modulo 16, not a fixed constant.
- [x] **GRID-CTRL-010**: A VSN1 module's endless encoder's push-button, which shares the encoder's own raw MIDI number (confirmed 2026-11-04 against real hardware, not a documented source fact), shall resolve to its own stable logical identity distinct from the encoder's own turn-generated events, disambiguated purely by message type (`Note On`/`Note Off` for the push-button, `Control Change` for turning) exactly as every other button role already is.
- [x] **GRID-CTRL-011** (Phase 1.2): A Grid runtime controller shall populate `knob_to_fader`/`mute_to_fader`/`fader_to_knob` for PBF4's Rotary (potentiometer) and Button elements, pairing `("grid_pbf4_pot", i)`/`("grid_pbf4_button", i)` with `("grid_fader", i)` for `i` from 1 through `bank_count`, by the same per-tag numbering `GRID-CTRL-002` establishes — mirroring a Korg `ControllerProfile`'s Knob/Mute bank membership, with no controller-family branch in any consumer (`MappingEngine`, Control Grouping, Control Descriptor). A VSN1-only topology shall populate neither mapping (empty, not absent).
- [x] **GRID-CTRL-012** (Phase 1.3): A Grid runtime controller shall expose `module_shape` — the ordered tuple of recognized module-type names in normalized left-to-right order, excluding unrecognized modules — and `control_module` — a mapping from every recognized logical key to its owning module's normalized ordinal and type. Neither field shall change the address-table resolution (`GRID-MIDI-*`) or any existing logical-key numbering (`GRID-CTRL-001` through `003`); both are additive read access to information already computed while walking the normalized module order.
- [x] **GRID-CTRL-013** (Phase 1.3): `module_count` (the count of distinct ordinals in `control_module`, equivalently `len(module_shape)`) shall be `1` for a single recognized module and greater than `1` for a multi-module topology; a static `ControllerProfile` shall expose no such attribute, such that a generic `getattr(controller, "module_count", 1)` read defaults to `1` for every non-Grid controller without a controller-family branch.

## MIDI Resolution

- [x] **GRID-MIDI-001**: The system shall compute each recognized element's expected MIDI channel as `(moduleY * 4 + currentPage) % 16` and its expected controller/note number as `(32 + moduleX * 16 + elementIndex) % 128`, using each module's absolute (un-normalized) `x`/`y` — never the normalized rank (`GRID-TOPO-009`) — per Grid's documented factory-default ("MIDI Auto") addressing.
- [x] **GRID-MIDI-002**: The system shall expect Note On as the message type for a button-role element and Control Change for every other recognized role.
- [x] **GRID-MIDI-003**: The system shall resolve an incoming MIDI event to a logical control via a single lookup against a precomputed address table built at topology-settle time, not a per-event re-evaluation of the addressing formula.
- [x] **GRID-MIDI-004**: Before a Grid topology has settled for the first time, the system shall resolve every incoming Grid MIDI event to nothing.
- [x] **GRID-MIDI-005**: WHILE the active Grid runtime controller is marked stale (`GRID-TOPO-012`), THE SYSTEM SHALL resolve every incoming Grid MIDI event to nothing, until the controller is rebuilt via an explicit reselection of Intech Grid as the active controller.
- [x] **GRID-MIDI-006**: An incoming MIDI event that matches no entry in the current address table shall resolve to nothing; the system shall not guess the nearest or most-likely-intended logical control.
- [x] **GRID-MIDI-007**: A resolved logical control's `MidiEvent` shall carry the original event's `channel`, `raw_value`, `normalized`, `is_press`, and `is_release` fields unchanged, with only its `type`/`number` fields rewritten to the resolved logical identity.

## Mapping Integration

- [x] **GRID-MAP-001**: A Grid-resolved logical control's `MidiEvent` shall be passed to the existing `MappingEngine.process()`/`process_websocket()`/`process_keystroke()` entry points exactly as any other controller's event is, via the same `_Key` dispatch; the system shall not implement a separate Grid-specific output path to OSC, WebSocket, or keystroke synthesis.
- [x] **GRID-MAP-002**: Bank/Group axis-assignment math (`docs/specs/static-mapping.md § MAP-WS-002`, `§ MAP-GROUP-*`) shall use the active controller's `bank_count` regardless of whether it is sourced from a static `ControllerProfile` or a runtime Grid controller, with no Grid-specific branch anywhere in the Mapping Engine.
- [x] **GRID-MAP-003** (revised Phase 1.3): The Preset Store shall persist and load a Grid runtime controller's (Bank, Group) axis-assignment table keyed by the active Named Controller's `id` (`docs/specs/named-controller.md`) and positional Bank index — no longer the fixed constant `"Intech Grid"` directly — using the same file format and the same caller-supplied `bank_count` bounds check (`docs/specs/static-mapping.md § MAP-STORE-003`) already used for static Controller Profiles, with no Grid-specific schema. `GridRuntimeController.name` remains the fixed display constant `"Intech Grid"` (`GRID-APP-001`'s dropdown entry text) — only the Preset Store key changes.
- [x] **GRID-MAP-004**: Loading a persisted (Bank, Group) entry whose Bank index exceeds the currently-connected Grid topology's `bank_count` shall be skipped with a logged warning, identically to the existing out-of-range handling for a static Controller Profile, and shall not be treated as an error.
- [x] **GRID-MAP-005**: Selecting, using, or persisting Grid as the active controller shall not alter the behavior, opinionated map, or persisted data of any existing static Controller Profile (nanoKONTROL Studio, nanoKONTROL2).

## Application Integration

- [x] **GRID-APP-001**: "Intech Grid" shall appear in the running app's Controller Profile dropdown as a selection distinct from every loaded `ControllerProfile`, represented without fabricating a static `ControllerProfile` instance for it.
- [x] **GRID-APP-002** (revised Phase 1.3): Selecting a Controller Profile dropdown entry — static or "Intech Grid" — shall cleanly disconnect/deactivate whichever controller was previously active before the new selection takes effect; selecting "Intech Grid" shall always start a fresh CDC discovery/settle cycle, including when reselected from `STALE`/`UNSUPPORTED`/`COLLISION`/`AMBIGUOUS` (Grid CDC-ambiguous). **Named-controller-ambiguity resolution (`docs/specs/named-controller.md § NAMEDCTRL-MATCH-004`) is a blocking modal dialog, not a persisted pending lifecycle state** — the dropdown itself is unreachable while it is open (ordinary modal behavior), so there is no "reselect while ambiguous" scenario to abandon; a cancelled dialog simply installs nothing (`NAMEDCTRL-AMBIG-001`), and reselecting "Intech Grid" afterward, once the modal has closed, restarts discovery fresh exactly as any other reselection does.
- [x] **GRID-APP-003** (revised Phase 1.3): The instant a `GridRuntimeController` settles (`GRID-TOPO-007`) while "Intech Grid" is the active selection, the system shall resolve a Named Controller for it (`docs/specs/named-controller.md § NAMEDCTRL-MATCH-*`) before installing anything. On an `Activated` resolution, the system shall install the controller as the active Mapping Engine/MIDI Input Adapter controller, load its persisted (Bank, Group) axis table keyed by the resolved Named Controller's `id` (`GRID-MAP-003`), and rebuild — not merely refresh — the Mapping View and Configuration Dialog to reflect its actual `bank_count` and logical control set. On an `Ambiguous` resolution, the system shall install nothing and shall hold the built `GridRuntimeController` pending user resolution (`NAMEDCTRL-AMBIG-001`), resuming this same installation sequence only once resolved.
- [x] **GRID-APP-004**: While "Intech Grid" is the active selection and no `GridRuntimeController` has yet settled, the system shall not poll ordinary MIDI device discovery.
- [x] **GRID-APP-005** (revised Phase 1.3): While "Intech Grid" is the active selection, the Status UI's existing connection-status text and error-dot state shall reflect Grid's current lifecycle status (waiting, CDC-ambiguous, initializing, active, unsupported, collision, stale, or — Phase 1.3 — named-controller-ambiguous) through the existing indicator mechanism, introducing no new widget; the CDC-ambiguous and named-controller-ambiguous states shall use distinguishable text, never identical wording (`docs/specs/named-controller.md § NAMEDCTRL-AMBIG-001`). While active, the text shall include the active Named Controller's `display_name`, not only the bare controller-family name.
